# Local setup

- Python environment: `uv venv --python 3.12 .venv`, then `uv pip install --python .venv/bin/python -e 'backend[dev]'`.
- Frontend locked install requires `npm ci --legacy-peer-deps` from `frontend/`; plain `npm ci` fails on missing peer dependencies in the existing lockfile. Do not regenerate the lockfile just to install it.
- Build city data from the repository root: `.venv/bin/python -m cityshift.citypack.make_pack toronto waterloo`.
- Backend: from `backend/`, run `../.venv/bin/uvicorn cityshift.api.app:app --host 127.0.0.1 --port 8000`.
- Frontend production preview: from `frontend/`, run `npm run build` then `npm run preview -- --host 127.0.0.1 --port 5173`. The `/world` route uses Babylon and needs no Mapbox token.
- Verification: `cd backend && ../.venv/bin/pytest -q`; from `frontend/`, `npm test`, `npm run lint` and `npm run build` (includes TypeScript checking).
- Browser playback checks: `node scripts/check-playback.mjs http://127.0.0.1:5173`. They require the backend and an existing city pack/scenario, mock simulation runs, and block other API writes. Set `CITYSHIFT_LIVE_REPLAY=1` to additionally verify visible car movement, pause/resume, and the activity jump against a real completed replay without modifying backend data. Set `PLAYWRIGHT_CHANNEL=chrome` to use installed Google Chrome when Playwright-managed Chromium is unavailable.
- `/` opens the globe; `/world` opens the city directly. Both use Babylon. Every globe destination routes to the Toronto prototype. `/mapbox` is the explicit Mapbox alternative and requires `VITE_MAPBOX_TOKEN`; no MapLibre fallback is mounted. `/world/lab` is the standalone renderer preview; `/showcase` is the isometric cityscape viewer.
- Product name: Concrete Consequences. Visual preference: minimal near-black UI, off-white type, thin borders, sharp corners, monochrome globe by default. No decorative orbital rings, wireframe, star field, blue HUD accents, or duplicate location sidebar. Locations are selected directly on the globe; configuration lives in Settings.
- Globe layout: Settings is docked permanently on the left (`SimulationSettings docked`), the globe sits in the centre, and Recent work (real scenarios/runs from the API, `frontend/src/globe/recentItems.ts`) is on the right. Selecting a recent item flies into Toronto and then selects that scenario; `store.selectScenario` is request-guarded so a slower earlier selection cannot overwrite it. The city keeps the Settings trigger button in its top strip.
- Globe input is rotation-only. Keep wheel and pinch zoom disabled and radius bounds locked to the viewport fit; only the scripted city-entry flight unlocks the radius.
- Info is clicked directly on the map, in any mode: buildings, buses, cars, people, stops and active closures. Agents, stops and closures outline in orange on hover (`Traffic.hoverId`, `NavOverlay.setHover`); buildings deliberately do not highlight or change the cursor on hover — only once clicked (orange roof caps + footprint edge). Click selects into the store (`Selection` includes `building`) and opens the info bubble (`shell/AgentBubble.tsx`: person / bus / car, stop, restriction, building). Priority under the pointer: entity or stop, then closure, then (while picking) the region, else the building. Buildings are picked on the CPU by testing the pointer's line of sight (`BabylonSyncMap.pickRay`) against every drawn prism — OSM footprints / reconciled sections, massing tiers, landmarks — in `babylon/buildingIndex.ts` (owned by `WorldScene.buildings`; heights mirror `architecture.ts`: `Y.building` lift, legacy 3 m minimum). Closures are the scenario's restrictions active at `clock.t` (`NavOverlay.incidentAt`); a closure's bubble pins to the closed segment nearest the view centre, a building's floats over its roof (`SyncMap.projectAt` / `buildingFacts`). Declared hazard tracks and unconfirmed hazard previews now render as tornado smoke and visual building damage; these visuals do not add structural or pedestrian simulation outcomes.
- City movement uses WASD relative to heading, E/Q for altitude, and Shift to hurry (`babylon/keyboardPan.ts`, owned by `WorldScene.keys`). Movement scales with orbit radius, stays within the countryside bounds, and keeps the camera above the terrain. Editable fields and hidden/globe views must not move the camera; disabling input stops residual velocity. Secondary-click drag (including a trackpad's two-finger click-and-hold) rotates; middle-button or Ctrl-left-drag pans. Babylon 9.26 requires an explicit `movement.input` rotation entry for button 2 after moving its pan binding to button 1. Manual input cancels camera flights and traveler following.
- City controls are deliberately simplified (upstream PR #2): no Compare split view and no free-text command bar; prompt-to-edit lives in the agents lens. Replays autoplay from `activityStart` (moving-track density computed by `buildIndex`); a scenario without runs auto-submits its baseline plan. Main viewers allow free orbit, pan, and zoom. There is no right-hand camera panel (City/District/Corridor/Agent/Incident presets and Egress were removed); programmatic framings still go through `cameraTo(pose, mode)` (city arrival, the bubble's Follow / Frame buttons, Area select) and `store.cameraMode` records the last one so the agent follow glide knows it is on. Resizing preserves the camera, `fixedCamera` is opt-in, and pointer/wheel/WASD input cancels an active flight and ends an agent follow.
- **Area select** is the first tool in the left rail (`ToolId 'area'`, `shell/ToolRail.tsx` / `AreaTool` in `ToolPanel.tsx`, logic in `world/areaSelect.ts`): its panel offers the **District** and **Corridor** pickers (keys `2` / `3` start the pick directly). Starting one closes the panel, frames every candidate (`framePose`), sets `store.picking` — the rail icon stays lit and the map cursor is a crosshair for the whole pick — and the city outlines the regions (`babylon/navigation.ts`; districts are Voronoi cells of the pack's zones + venue from `babylon/regions.ts` — a geometric stand-in, not real neighbourhoods; corridors are `corridors.json` in `store.corridors`). Only while a pick is open does hovering a region tint it orange (`--hover`, `#f5891f`) and show its name tag (`NavLabels`); clicking flies in (`districtPose` / `corridorPose`) and closes the pick, so nothing stays marked. Escape closes the pick (or, with none open, the info bubble); choosing another tool ends a pick, closing the panel does not.
- `BabylonSyncMap.unprojectGround` intersects the line of sight with the ground plane from camera geometry rather than NDC depth, so it holds in both projections and with the reverse depth buffer; `metresPerPixel` converts pointer tolerances to ground metres.
- Investigation preferences (AI enablement, candidate count, reasoning steps, Elasticsearch use) are persisted in the browser and snapshotted into each investigation. AI-off also disables the LLM fallback for edit previews. Provider credentials remain server-side; preferences never start services or store keys.
- Globe imagery and country borders load from public three.js / Natural Earth sources; the globe can still select destinations if external imagery fails. The Toronto scene prewarms behind the globe, with city rendering and keyboard shortcuts suspended while hidden.
- After changing the world compiler, regenerate each existing pack with `.venv/bin/python -m cityshift.citypack.world toronto` (and `waterloo`). Restarting the server alone does not regenerate the JSON.
- Terrain surface partitions preserve intersection precision. Do not round their exported vertices to the source geometry’s 0.1 m grid: this creates overlapping slivers at angled boundaries.
- `babylon/terrain.ts` is decorative, seeded countryside, not surveyed geography or part of SUMO. The compiler supplies `far_water`, `far_bounds`, and `surfaces.meadow`; roads extend from terminal network nodes. Land is cut out under lake polygons (preserving islands), fields, and rural roads. All rural surfaces and placements use the same sampled heightfield; merely evaluating the noise independently produces intersecting surfaces. Unclassified city ground matches meadow, while explicit asphalt/pavement remains unchanged.
- Overlapping building footprints are reconciled into vertical sections with exposed roof polygons. Preserve `source_id` / `source_height` for appearance, render `roofs` rather than the full footprint, and never apply the legacy 3 m minimum height to reconciled sections.
- Cosmetic placements must query `BuildingIndex.overlapsCircle` (including official massing, landmarks, courtyards and height bands), not only the remaining OSM buildings. `PlacementGrid` reserves complete tree/prop extents; park trees are passed into street placement, and both park and street trees seed `TerrainOptions.reservedTrees` so the countryside cannot overlap them across the pack boundary. Rural surfaces share priority reservations so crossings are cut rather than stacked. Decorative shelters may move off vehicle lanes, but stored stops and measured traveler positions must not be changed to disguise rendering problems.
- Official Toronto massing (`frontend/public/assets/city/toronto-massing.json`) is never rendered raw. `cityshift.citypack.massing.prepare_massing` verifies alignment (matching network, embedded coordinate frame, or the verified legacy asset hash + CN Tower anchor), reconciles overlapping tiers, clips OSM fallback footprints, and writes `var/citypacks/toronto/massing.json`, served at `/api/packs/toronto/massing`. Regenerating Toronto (`python -m cityshift.citypack.world toronto`) refreshes it.
- City camera: perspective is the product default (globe arrival). `/showcase` and `/world/lab` opt into isometric via `camera.setPreferredProjection`; the Settings drawer exposes Overview and Lighting for the full app.
- The Babylon city uses PBR materials, the textured cloud sky with the world-edge fade plugin (no scene fog), landmark GLBs and street furniture from main, on top of the world-aligned single shadow map. Street details and trees are placed on the compiled surface height and keep `TREE_CLEARANCE` from building footprints.
- The renderer uses reverse depth. In Babylon 9.26, `DirectionalLight.shadowFrustumSize` does not reverse the projection depth; use explicit orthographic bounds with automatic extent updates disabled. Shadow tests cover both depth order and camera-independent projection.
- `/live` is the persistent SUMO intervention mode, reached from the city top strip. Its optional original/edited branch comparison is separate from the deliberately simplified recorded-run viewer; do not restore the removed main-app comparison or free-text command bar.
- Live sessions use `/api/live` and store append-only CSF1 trajectory chunks plus command logs under `var/live`. Each browser pane holds at most six ten-second chunks. The playhead must never advance beyond loaded, simulated time.
- `CITYSHIFT_PACK_ROOT` can select existing city-pack inputs for an isolated worktree; live recordings still belong to that worktree. Keep the SUMO network fingerprint consistent with the displayed world.
- Past live edits restore the seed and prior commands into a child session. Preserve the parent's recorded prefix and all individually identified travelers; never substitute decorative crowd counts. The cold-response model is explicitly synthetic and does not create road ice.
- Repeated dynamic bus visits require TraCI `insertStop(..., teleport=0)`: repeated `setBusStop` calls update existing stops instead of appending later visits. Regression tests cover service added after travelers are already waiting and valid spawn positions on 0.2 m pedestrian segments.
- `/tornado` is the visual sandbox, linked from the city top strip. It reads city geometry but does not submit SUMO runs or change saved scenarios. T arms placement; drag/scroll sizes it, R/Shift+R rotate the travel direction, 1–5/Shift+scroll set power, F toggles travel, and Escape/right-click cancel. Clear storms restores the city; the timeline reconstructs effects from absolute time.
- Tornado placement suspends both pointer camera controls and `WorldScene.keys` while aiming, then restores their previous state. Keep the main city's WASD/navigation bindings and current mouse-pan configuration intact.
- Building destruction uses `city.buildingRanges` and `setBuildingsHidden` to substitute animated copies for selected static geometry. Preserve source IDs, reconciled sections and material sharing with terrain; do not rebuild or replace the complete city for an effect.
- Reload after changing imperative Babylon classes; HMR may keep old scene objects alive. For browser drag checks, use a background tab with CDP focus emulation so foreground mouse input cannot cancel pointer capture.
- Incidents (`kind: "incident"`, `cityshift/live/contracts.py` `HAZARDS`) are posted like any other live command. `cityshift/live/swarm.py` is the agent-to-agent layer: travelers inside the warning radius witness an event (hop 0); informed agents pass it to neighbours within reach with a seeded probability, cooldown and hop budget. Envelopes mirror openJiuwen's `MessageEnvelope` fields but are delivered by the in-step proximity router, never the async LLM bus.
- Vehicle blocking uses SUMO lane permissions (announced road closures reroute everyone; incidents reroute only informed drivers). Pedestrian avoidance is planned by us (`LiveNetwork.walk_around`, `escape_path`), not by lane permissions, because SUMO cannot reroute a person standing on a disallowed edge.
- The spare uint16 in each CSF1 row carries alert flags (`frontend/src/live/flags.ts`): aware level/hop, responded, in-zone, trapped, fresh. Figures (`frontend/src/babylon/figures.ts`) pick a pose from measured speed; `display.swarmScale` enlarges models only, never positions. Vehicles scale more gently and far-LOD pins get a camera-distance boost.
